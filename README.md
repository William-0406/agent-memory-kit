# 个人记忆库工具包

给你的 AI 助手一套存得住、查得到、能核对的长期记忆。用 Markdown 文件存，不装数据库，零依赖。

这个仓库是我自己用了几个月的那套记忆库的骨架。数据全部清空，模板留成占位符，机制、脚本、检查规则照旧。

## 最快开始：把这段发给你的 AI 助手

你不需要看懂下面的命令。**把下面这段发给你自己的 AI 助手，它会自己装好。**

```text
请帮我在当前目录装一套个人记忆库，仓库地址是：<把这里换成仓库地址>

步骤：
1. 先确认 Node.js 版本 ≥ 18：node --version
2. 克隆下来（如果当前目录已经就是这个仓库，跳过这步）：
   git clone <上面的地址> && cd <仓库名>
3. 安装，把「我」换成你对我的称呼：
   node scripts/init.mjs --owner "我"
4. 装完读一遍根目录的 AGENTS.md，那是你之后每次开工的入口规则。
5. 把安装过程中报的「失败」项原样告诉我，不要自己编造仓库里没有的文件。
```

你不用管上面是什么意思，原样转发就行。**唯一要改的是仓库地址**，还有第 3 步的称呼。

装完之后，每次开始一个任务，助手会自己跑开场入口，把该读的记忆读出来。

如果你想自己动手，等价的三条命令是：

```bash
git clone <这个仓库的地址> memory-kit
cd memory-kit
node scripts/init.mjs --owner "我"
```

## 装之前需要什么

| 需要 | 说明 |
|---|---|
| **Node.js ≥ 18** | 唯一必需的运行环境。低于 18 脚本会直接告诉你版本不够并以退出码 2 结束。 |
| **git** | 强烈建议，但不是起步必需。仓库里有 5 处会调用 git：`memory-gateway.mjs` 用 `git ls-files` 决定扫哪些文件；`memory-check.mjs` 用 `git diff` 判断本次改了什么；`l3-review.mjs` 用 `git ls-tree` / `git cat-file` 核对审阅记录是否已提交；`safe-commit.sh` 和 `.githooks/pre-commit` 本身就是提交环节的东西。 |

**没有 git 会怎样**（这是实测的，不是推测）：

| 命令 | 没有 git 时 |
|---|---|
| `init.mjs` | **正常**。装完会提示你 `git init`。 |
| `memory-startup.mjs --check` | **正常**。只算预算，不碰 git。 |
| `memory-startup.mjs --query "…"` | **正常**。列文件时退回目录遍历，和用 git 的结果一致。 |
| `memory-check.mjs` | **明确告诉你它没法检查**（"这不是检查通过，是没法检查"）。带上 `STRICT=1` 时退出码 1。 |
| `l3-review.mjs` | 正常退出，但核对不出记录是否已提交——L3 审阅留痕本来就是"提交过的才算"。 |
| `hook-run.mjs` | 前三步能跑；没有 git 就没有 `git commit`，钩子本身也用不上。 |

所以「没有 git」不会让开场检索这条主路径坏掉，但**体检和 L3 核对会失效**，而体检是这套库最值钱的部分。**能装 git 就装上，再 `git init` 一次。**

**不需要 `npm install`。** 这个仓库零依赖，`package.json` 里 `dependencies` 和 `devDependencies` 都是空的。所有脚本只用 Node 内置模块。

## 目录结构

只列到目录级，具体文件看模板。

| 目录 | 放什么 |
|---|---|
| `templates/` | 所有模板文件。安装时复制到根目录，把占位符替换成你的称呼。 |
| `scripts/` | 全部脚本：安装、开场检索、体检、记忆网关、L3 审阅检查。 |
| `config/` | `profile.json`（你的实际配置）和 `profile.example.json`（示例）。 |
| `docs/` | 设计说明。想知道为什么这样分层的看这里。 |
| `.githooks/` | 提交前自动跑检查的钩子。 |
| `.github/workflows/` | CI，跑测试用。 |
| `交接/` | 每次干活的接力记录，按月分目录。装完后才开始有内容。 |
| `工作/` | 每个项目一份，记状态和判断。 |
| `知识/` | 跨项目复用的长期知识。 |
| `记忆网关/` | 检索索引、回归案例、审阅记录。 |
| `生活/`、`语料/`、`归档/` | 日志简报、原始材料、过期内容。安装时创建。 |

## 你的配置：`config/profile.json`

安装脚本会生成这个文件。四个字段，但**它们现在的实际作用不一样**，下面按实测写：

| 字段 | 现在的值 | 实际作用 |
|---|---|---|
| `owner` | `"我"` | **真的在用。** 五个脚本加一个测试导入它：模板里的 `{owner}` 被替换成它；`memory-check.mjs` 用它判断一句话是不是「把话算在你头上」；`memory-gateway.mjs`、`memory-startup.mjs`、`rule-scores.mjs`、`speaker-map.mjs` 都读它。改了之后重跑 `node scripts/init.mjs --owner "新称呼" --force` 才会更新已生成的模板文件——只改 JSON 不会回头改 AGENTS.md 这些已经生成的文件。 |
| `handoffSides` | `["codex","kimi","workbuddy","dsh"]` | **真的在用。** `memory-check.mjs` 和 `rule-scores.mjs` 按这份名单拼正则认接力文件名（`2026-01-01_1200_codex.md`）。**新接一个助手记得加进来**，否则它写的接力在所有检查里等于不存在。 |
| `timezone` | `"Asia/Shanghai"` | **目前只影响安装那一刻**：它决定 `config/profile.json` 里记什么，以及安装时 `{timezone}` 的替换（现有模板里没有用到这个占位符）。`profile.mjs` 导出了 `TIMEZONE`，但**没有任何脚本导入它**——改它不会改变已有文件里的日期，也不会改变「距上次多少天」的算法。真要按别的时区工作，得改脚本。 |
| `lang` | `"zh"` | 同上，`profile.mjs` 导出了 `LANG`（只接受 `zh` / `en`，别的一律退回 `zh`），但**没有脚本导入它**。现在改它没有可见效果。 |

上表后两行是这套骨架的已知缺口，不是文档漏写。如果你要按多时区或多语言用，得自己把它们接进脚本。

`config/profile.example.json` 是同一份内容的示例，可以照格式复制成 `config/profile.json`。

## 用法

### 开场检索

每轮任务开始时跑一次，把该读的记忆读出来：

```bash
node scripts/memory-startup.mjs --query "帮我看下 XX 项目的进度"
```

只查预算、不看内容：

```bash
node scripts/memory-startup.mjs --check
```

`--check` 会报出本次开场要读多少字符。上限 20000，其中入口最多 18000，预留 2000 给后续下钻。超了就要缩短入口，而不是抬高单文件的阈值。

### 提交前体检

```bash
node scripts/memory-check.mjs        # 只看已暂存的改动
node scripts/memory-check.mjs --all  # 看工作区全部改动
STRICT=1 node scripts/memory-check.mjs  # 严重问题直接以退出码 1 结束
```

默认只警告不拦截。想让它真的拦住提交，把 `STRICT=1` 写进 `.githooks/pre-commit`。

想连提交动作一起管住，启用钩子：

```bash
git config core.hooksPath .githooks
```

启用后每次 `git commit` 会依次跑四步：开场预算、记忆库体检、回归案例、自动化测试。任何一步失败都会停下，并告诉你卡在哪一步。确实要跳过就用 `git commit --no-verify`，并在提交信息里写清为什么跳过。

钩子依赖于你在仓库根目录执行 `git commit`（它按仓库根目录找脚本）。用图形客户端提交时，如果客户端的工作目录不在仓库根目录，钩子可能跑不起来——那种情况下先手动跑一次 `node scripts/hook-run.mjs` 再提交，效果一样。

### 跑测试

```bash
node --test
```

**注意别写成 `node --test scripts/`。** 从 Node 21 起，那种「传一个目录」的写法会被当成模块入口去解析，直接报 `Cannot find module '.../scripts'`，一个测试都不跑。不带参数时测试运行器会自己发现 `**/*.test.mjs`。`npm test` 已经配成正确的形式（`node --test`），CI 用的也是它，钩子里的第四步同样是它。上面这个结论在 Node 24 上实测过；18、20、22 未逐版本实测，但用的都是同一个发现机制。

## 这个仓库里没有什么

- **没有真实的个人数据。** 所有记忆文件都是空模板或占位符，`{owner}` 会被换成你自己的称呼。`交接/`、`工作/`、`知识/` 装完之后才开始有内容。
- **模板是占位符，不是范例。** 它们说明结构长什么样，里面的条目要你自己填。别把模板里的示例当成别人的真实经历读。
- **不是知识库，也不是笔记软件。** 它不提供界面、搜索和同步，只管文件的组织方式和检查规则。
- **没有云端。** 全部是本地文件，版本保护靠你自己的 git。
- **没有 LLM 调用。** 所有检查都是确定性的字符串和文件判断，不联网。

## 关于隐私

`config/profile.json` 会写进你的称呼，`.gitignore` 里没有排除它。要不要把它提交上去，自己判断——如果你打算把仓库推公开，先看一眼里面有没有不该露出的信息。

`记忆网关/运行时/` 下的索引是脚本随时重建的缓存，已经排除。真正的正文（`templates/`、`记忆网关/回归案例.jsonl`）是故意不排除的。
