# 为什么这样设计

这份文档给想改这套系统的人看。下面四条都是真正的取舍，每条写清「替代方案是什么、为什么没选」。不同意可以改，但改了要知道自己换掉了什么。

## 一、存成 Markdown 文件，不用数据库

替代方案是向量库或文档数据库：检索更准、能存几十万条。没有选。

理由是这套记忆的读者不止是人，还有 AI。Markdown 谁都能直接读，`git diff` 能看清一句话哪天被谁改成什么样，用错了当场手改回来。数据库要走一层查询接口，出了问题得先有个能跑通的环境，而记忆库最怕的正是「坏了打不开」。文件还能被任何助手无条件读取，不依赖它认不认识你的库。

代价说清楚：文件多了检索会变慢，超过几千份就该换方案。这一版默认你写不满。

## 二、分 L0~L3 四层，上层带触发条件

替代方案是平铺，所有内容放一处，或者干脆不分类。没有选。

真正的问题不是分类，是**只有下层会自动长**。事件每天新增，长期结论没人写——因为写长期结论靠自觉。所以这版给 L3 定了个机械触发条件：自上次有效审阅或回写以来，`交接/` 新增 ≥ 3 份，或距上次 ≥ 7 天，就必须回头审一遍积累的内容。有值钱的才写进去，没有就在接力里记一笔审阅范围和理由。

「3 份」和「7 天」是拍出来的，不是算出来的。改的时候挑一个你会真的响应的数，别挑一个听起来严谨的。

## 三、每条事实带来源标记，标记只进文件

替代方案是不要标记，靠记忆规则约束。没有选——规则靠自觉，标记可以查。

标记的作用不是好看，是把「谁说的」和「事实」绑在一起。`[先验:助手]` 明确表示这是模型的推测，不能当某个具体人的事实用；`[待查]` 表示还没核实。没有这层区分，一句猜测混进长期记忆后会被反复引用，越引越像真的。

还有一条容易被改坏的：**标记只写在文件里，跟人说话时一个都不许出现。** 标记是给审阅和检查用的元数据，读出来就是噪音。这条不是洁癖，它决定了标记能不能被允许存在——不能读出声，才敢标得这么细。

## 四、开场有 20000 字符的预算

替代方案是「读到够用为止」，凭判断。没有选。

上下文是有限的，而「够用」没有刻度。所以这版把预算拆成了数字：开场入口最多 18000 字符，预留 2000 给按需下钻，脚本每次开场都能报出实际用量。超了就缩短入口，而不是抬高单文件阈值来掩盖总量增长。

这样做唯一的好处是**可核对**：从「我应该少读点」变成「18000 这个数超没超」。代价是有时需要主动砍掉想读的内容——这就是它的用途。
