# Codex / Kimi 接力规则

> 目标：上午在 Codex 聊过的事，下午打开 Kimi 能立即接上；反过来也一样。
> 接力记录是助手摘要，不是 {owner} 原话，不能拿去训练 `语气档案.md`。

## 一、共同原则

- 本目录是双方唯一共享的事实来源，不依赖各自的内置记忆碰运气。
- 每个助手写自己的接力文件，不能覆盖另一个助手的文件。
- 不等“对话结束”才交接。每完成一个有后续价值的阶段就及时更新，避免关掉窗口后丢失。
- 闲聊、临时问答和随时能重新查到的公开信息不用记录。
- 交接只解决短期连续性；稳定事实、决定、承诺和知识仍写进原来的长期文件。

## 三、什么时候写

出现以下任一情况就更新当前接力文件：

- 做出了决定，或明确排除了一个方案
- 完成了任务、修改了文件或生成了产物
- 发现了重要事实、风险、限制或前后矛盾
- 有尚未解决的问题需要另一个助手继续
- {owner} 明确说“先这样”“明天继续”或准备切换助手

🆕 **[2026-10-28] 两处补充（来源：Claude Code 团队 code review 流程）**：

- **「误报」列只在审查类任务填**（页面/UI 自查、代码复核、文档核对、检索验收）；日常问答不填。填的数字必须与 `记忆网关/审查台账.jsonl` 当日那一行一致，否则台账和接力会分叉。审查类任务**没误报就写 0**，不能留空——空白和「没记」在文件里长得一样，计分就假了。
- **验证结论只对当次改动有效**：写了「已验证」，之后任何人再改一行，这个结论即失效。接力里若引用旧验证，必须写明验证的是哪个版本/提交，不许拿旧结论当新证据。

没有内容的章节可以删除。摘要要短，但必须保留决定理由、未解决问题和相关文件。

## 六、沉淀到长期记忆

接力完成后，再判断是否需要同步到：

- 稳定事实 → `我是谁.md`
- 决定和排除理由 → `决策记录.md`
- 未闭环事项 → `待办与承诺.md`
- 项目进展 → `工作/<项目>.md`
- 日常事件 → `生活/日志/<年-月>.md`
- 有长期价值的知识 → `知识/<主题>.md`
- 对 {owner} 的观察、助手的立场、稳定的局限或不确定 → `助手侧记.md`
- 助手出的错（经过与归因）→ `纠错记录.md`；可执行的拦法 → `自检规则.md`

不要把同一句话机械复制到所有文件。
