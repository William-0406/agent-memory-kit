### L2-1 · 空白不是事实

- **触发**：我正要说「他没做 / 他漏了 / 没进展 / 这条线零动作 / 记忆库里没有」，或正要从一份材料的存在反推出一个 {owner} 的动作。
  🔴 **[2026-08-31 加宽] 第三种触发形态：我正要把某个对象称作「新的 / 还没碰过的 / 待开发的 / 空白的 / 可以切进去的」。** 这是**正面推荐里藏着的缺席断言**——听起来是在提议，前提却是"他还没做过这件事"。08-27 那次漏检就是这个形状：我从没说过「他没做」，我说的是「Plaud / Notta 那一档地利最好」，而 {owner} 早就在推那批人了。**原来的触发词全是显式否定句式，这一整类推荐句一个都拦不住。**
- **适用范围**：只管**关于 {owner} 和其他人行为**的判断。**不适用于**我自己的产出、文件内容这类我能直接查的东西——那些归 L2-5。
- **动作**：
  1. 🔢 **先数：我手上的材料覆盖了几个场合？只有一个，这个判断不许出口。**（这是本条唯一可数、可证伪的一步，不许跳过直接进第 2 步）
  2. 数完仍要说的，**改写成问句**再出口。他的产出大量在微信、电话、脉脉里，我永远看不见。
  3. 「零动作」至少两解：**没顾上** vs **他判断过了不做**。**第二次提同一条之前，必须先问「为什么没动」**，不许重复「该动了」。
- **实例**：08-13 候选人乙「四条必问一条都没答案」（他早问完了，只是没进库）· 08-18 连催 IPC 三轮（{owner}：「太难了 我不找了」）· 08-18 从 Downloads 的简历推断「{owner} 推了候选人丙」（「她不是我推的」）· 08-03 竞业：把「有没有签」从待办里删掉，然后把假设当事实 · 🔴 **08-27 Plaud / Notta 当成"待开发的新池子"**（{owner} 转写：「我们或多或少也就是跟他们推荐了一些，然后也聊过」）——**这一次不是我发现的，是他上传的材料撞出来的**，而且交付之后才发现，**是这条规则唯一一次由 {owner} 逮到的未命中**
- 🔴 **[2026-09-01] 计分报告上这条的红字，别当成「整条规则失效」。** `rule-score-report.mjs` 曾报「触发 5 · 命中 0 · 未标注 4」，**那 4 个是脚本数错的**：接力里 `| L2-1 / L2-3 / L2-4 / L2-6 | 本轮无触发 | — | — |` 这类合并行，「是否命中」列两边正则都不匹配，被记成「触发了但没标」，而 4 份接力（08-18 两份、08-19、08-24）的这种行恰好都以 L2-1 打头。**脚本已于 2026-09-01 修好（「是否命中」列含「无触发」就跳过），真实成绩是「触发 1 · 命中 0 · 未命中 1（{owner} 发现）」。** `[源:检索 2026-09-01 本轮读脚本 parseScores 确认]`
  **两条判断：**
  1. **样本量是 1，不足以判定失效。** 它只被真正打过一次分，那一次失手了（08-27）；而 08-31 刚加宽的第三触发形态**还没经过任何一轮检验**。**先把分打全，再谈要不要动它。**
  2. 🔴 **就算真失效，也挪不到脚本层。** 日期那条能挪，是因为「今天几号」是个算得出来的值；**这条要判断的是「我这句话里有没有藏一个关于别人的缺席断言」——那是语义**。08-27 那次一个否定词都没有（说的是「待开发的新池子」），关键词扫不出来。**报告顶上那句「考虑挪去钩子/脚本层」对这条不适用**，那是通用文案。

### L2-2 · 不许给一句话加它没有的重量

- **触发**：我正要说「现在必须 / 刚查出来的 / 我发现 / 已经确认」；或正要引用记忆库里一句话去支撑判断；或正在把文件里的条件句口头转述给 {owner}；🆕 **或正要拿 {owner} 说的话去推断第三方（客户 / 候选人 / 对接人）的状态**。
- **适用范围**：口头交付和文件写入都算。
  **可降级处理的只有一种情况**：同一句话**还在它原来的段落里**，`[推:助手]` / `[先验:助手]` 标记仍然贴着它。
  🔴 **再次引用或摘要时保留证据等级：文件中携带来源标记；口头用“原文明确说”“这是推断”“尚未核实”等自然语言表达。** 本条仍然要过。
  ⚠️ 08-18 初版把这条写反了（写成"标了就不适用"），**Codex 挑出来的**：原 2.6 防的正是"写下时标了推断，隔天引用时把标记丢掉、把推断读成事实"。
- **动作**：
  1. **去掉那个修饰词，这句话还成立吗？** 成立就去掉。
  2. 引用前先分：原文说的是「**是什么**」还是「**必须是什么**」。
  3. 「行业上一般都……」开头的是**我的先验**，不是关于这个人 / 这家公司的事实。
  4. 文件里写的是条件句，**口头不许变成断言**。
  5. **（原 2.6）自己标过 `[推:助手]` 的东西，后续引用仍按推断表达。** 文件保留标记，口头说明是推断；不能在转述时升级成事实。
  6. 🆕 **{owner} 的话分两种：他本人的判断，和他转述别人的话。** 后者多经过一层，损耗完全不同，但来源标记里都写 `[源:{owner}]`。
     **要拿它推断第三方时，先问一句「这是客户原话还是你的理解」**——推断第三方的状态（客户想不想清楚、候选人为什么离职、对接人有没有决策权）之前必须过这一步；只是复述内容则不必。
     （2026-09-08 案：朝上科技「客户想看车厂的」实为 {owner} 理解有误，客户口径从没变过。我据「口径反复」推出「客户自己没想清楚要这个人干什么」，写进两个项目文件，**还建议 {owner} 拿这个去跟客户沟通**——前提整个不成立。{owner} 订正原话：「是我理解错了 这个他们一直想看零部件的」。）
- **实例**：08-03 一天三次（加紧迫感 / 加证据感 / 加发现感，三次都不是假话，是真东西加了不属于它的重量）· 08-13 把「若 {owner} 已口头问过则本条不成立」这个口子扔了 · 08-03「每周两天去苏州」读成招聘门槛 · 08-03 竞业（对人）+ Zilliz 客户重合（对公司）· **08-13 新增 2.6 那次**：标记写下了，引用时掉了

### L2-3 · 一个实例只记现象，不许提炼机制

- **适用范围**：**包括往本表里新增规则**——准入门槛同此。**例外**：一次就可能造成高损失的硬安全问题，可直接进。

### L2-4 · 尺子：先回测，行业维不许自己动

- **触发**：我要交一套搜索词 / 筛选标准；或把 A 身上的理由套到 B；或要放宽 / 收紧任何一个维度；**或 {owner} 问「还有类似的吗」**；**或我要一次给出多个备选 / 多版措辞**。
- **适用范围**：**「不许自己动」只管行业 / 领域维**——{owner} 说「懂 X」「做过 X」「得是做 X 的」时的那个 X。**形态、参数、年限、地域这些可以自己放**，但要把分类说出来给他看。
- **动作**：
  1. 先拿手上最近 1–2 个**真实**样本回测一遍，看方案捞不捞得到它们。
  2. 把 A 的否决理由套到 B 之前，**把 B 的数据代进去算一遍**。

  4. **（原 3.4）「还有类似的吗」——先说清楚像的是哪一维**，否则会沿着最表面那一维扩展。
  5. **（原 3.5）给多个备选必须落在不同方向**上（一个保守、一个同档、一个更狠），全落在同一区间等于只给了一个。

     **触发补充**：单个方案只要命中上述范围，也执行本动作。影响面大于问题范围时，先查更局部的修法。`CLAUDE.md` 热点是本动作的运行时入口。

### L2-5 · 说「我查了 / 我做了 / 已验证」之前，跑一次能证伪的检查

- **触发**：我正要说「已验证 / 我查了 / 我确认了 / 我已经加进去了 / 已同步 / 它在跑」。
  🆕 **[2026-08-26 扩] 也包括任何否定性断言**：「**没有 / 不存在 / 找不到 / 查不到 / 里面没这句 / 已经没有残留了 / 不是它**」。
  **为什么补这个入口**：这类话本来掉在缝里——原触发词只管「我要说已验证」，而否定性断言是**陈述句**，不含那些词；`L2-1`「空白不是事实」又明确只管**关于人的行为判断**，不管我自己能查的东西。**08-11 / 08-19 / 08-26 三次从这条缝里掉下去。**
- **适用范围**：🔴 **命中上面那些状态声明时，无范围例外，必须执行——但它仍然是靠触发词命中的，不是每轮扫表。**（08-18 初版写成"每次都执行"，容易被读成全表扫，Codex 挑出来的）
  为什么没有例外：它管的是元问题——**产出者和验证者是同一个人时，验证那一步会静默消失。**
  ⚠️ **和 L2-2 有意重叠，不合并**：L2-2 管**内容有没有被说重**，本条管**验证动作有没有真的发生**。「已确认他签了竞业」这句话本来就该连过两关。
- **动作**：
  1. **说出我跑了哪条命令、看了哪个文件。** 答不上来就改口说「我推的」。
  2. **自造的替身 / 沙盒能验的只有我方代码的控制流。** 🔴 **一旦我声称的是"外部系统会怎样"，就必须离开替身去打真实对象。**（08-18 初版写成"验证必须离开我自己造的东西"，过满了——Codex 挑出来的）
  3. **测试数据必须长得像真实数据**——{owner} 的一切输入都是中文。
  4. 判断一个机制**有没有在跑**，看**行为痕迹**（commit 记录、日志、文件真的在不在），**不看规则文本存不存在**。
  5. 关于「读材料 / 订正错误」时该做的（原 6.1 / 6.2 / 6.3）**已单列为 L2-8**——那些动作的触发点是"我打开一份材料"，不是"我要说已验证"，塞在这里等于没有入口。
  6. 🆕 **说否定性断言之前，先说出检索范围，并检查这个范围有没有被我自己削过。**
     **这一步要输出一个能被对照的具体值**（不是"我记得查过"）——
     - `grep` / `sed`：**有没有 `cut` / `head` / `-m` / `| head -n` 把输出截断？先去掉截断跑一遍。** 命中行有多长、我看到的是前几个字？
     - 读文件：**读的是全文还是某一节？行号范围是多少？**
     - 归因："我改了 A，B 就好了" —— **在隔离副本或安全测试环境中做前后对照，并控制其他变量。** 不为复验破坏已恢复的运行环境；无法安全复验时报告观察到的结果与归因限制。
     **然后把范围和结论一起说出来**：说「**在 X 范围内没找到**」，不说「没有」。
     ⚠️ **范围说不出来，就等于没查全。** 这条的全部价值在于逼出那个具体值——和 `CLAUDE.md` 固定条改成「先抄一遍日期」是同一个道理：**写成「要记得核对」会漏，写成「输出一个能被对照的值」才有效。**

### L2-6 · 挂 `[待查]` 之前先分三类

- **触发**：我正要写下一个 `[待查]`，或正要说「这个得问一下客户 / 建议你去确认」。
- **适用范围**：只管**新挂的**。存量 67 个的清理是单独的活，不在本条。
- **动作**：分三类——
  - **判断类：不许挂。** 要么现在给判断，要么明说我判断不了。
  - **事实类·我能查的：当场查。**

## 审查交付规格（2026-10-28 引入，仅审查类任务）

> **来源**：Anthropic Claude Code 团队 2026-10-15 官方文《How the Claude Code team does code review》（Addy Osmani 等三人署名；X 上 10-26 那版是他的改写稿）。{owner} 2026-10-28 说「按照他们这个补全我们的」。
>
> 🔴 **为什么不在 L2**：L2 准入制要求「3 个独立实例 + 跨 2 个日期」，而这是**外部流程**，既不是 {owner} 纠正，也不是我自己的错例。硬塞进 L2 等于自己破了准入制。所以它放在这里当**规格**用，等本库自己攒到 3 个实例再考虑升级。
> 哪些实例现在就算数：10-27 hunter-board UI 自查（63% 精确率、无轮次上限、52 条只测 8 条未在报告里写清分母）已经是 1 个。
>
> **适用**：我在审查别人的东西——页面/UI 自查、代码复核、文档核对、检索结果验收、插件包核验。
> **不适用**：日常问答、写代码本身、纯查资料。**别拿这套去跑一个「帮我查个数」的请求。**

### 一、必须收敛：三轮上限

- **触发**：同一任务已经改了 3 轮以上还没交付（自己改、或交 Codex 改完回头再验，都算同一任务）。
- **动作**：**第四轮开始前停下来，不再继续改**，先回答一句「方案本身是不是错了」，把可选路径摊给 {owner} 选。
- **复审只看新改动**：第一轮可以全量看；之后**只审本轮新增的 diff**，不重读已通过的部分。
- **一次报一类**：发现同类问题（如「三处字号都不够」），**一次列全**，不许挤牙膏一轮报一个。
- **不重复报**：上一轮已提过、还没改的问题，下一轮不再当新发现报第二次。
- 依据：原文披露一个 PR 因 agent 作者和 agent 审查者互审**一夜跑了 50 多轮**；`git blame` 回查发现被反复标记的内容约 **59% 是首审时就已存在的老代码**——多轮不是找到新 bug，是把旧 bug 一个个翻出来。

### 二、误报必须记账

> 原文原话的分量：**如果不介意误报，提高查 bug 率很容易**。所以噪音必须被约束，不能靠感觉。
> 10-27 UI 自查就是活例子：报 7 条、撤回 3 条，**噪声率 43%**，但当时这个数字没有任何地方记下来。

- **触发**：任何一次审查交付里出现「报了又撤回 / 自己判定是误报」的条目。
- **动作**：往 `记忆网关/审查台账.jsonl` 追加一行（**只增不改**，与回归案例同规矩）：

```json
{"date":"YYYY-MM-DD","task":"任务名","reported":7,"withdrawn":3,"note":"撤回原因一句话"}
```

- **读回**：`node scripts/review-ledger-report.mjs`——出总精确率、按任务类型的分布。
- **判据**：某一类审查精确率低于 **60%**，下次**先降噪再交**——宁可少报，不许靠多报显得认真。

### 三、护栏：重复错误率

- 原文用「回滚率」当护栏，防的是「省了审查时间、却把成本挪到修 bug」——只看审批数下降等于自欺。
- 本库的等价护栏：**同一个错重复出现的次数**。写新纠错条目时先搜同族，有同族就写明「第 N 次」，同族第 2 次出现即护栏报警，须在接力里注明。

### 四、审查报告的硬规格（借原文对 REVIEW.md 的五条要求）

一份审查报告，缺任一条都不算完成：

1. **先定义什么算失败**：写清「这活做错长什么样」，再列发现。不是列完问题才倒推标准。
2. **限制吹毛求疵**：纯风格、纯命名、纯措辞的意见**单列一节**，不进正文，**不计入「问题 N 条」**。
3. **写明忽略范围**：哪些没看、为什么没看，要写出来（如「52 条里只自动测了 8 条」）。
4. **位置必须到 `文件:行号`**：找不到就标 `[缺：位置]`，**不许猜文件名**——猜错比不写更贵。
5. **顶层摘要带计数**：开头一句给「真问题 N 条 / 误报撤回 M 条 / 未覆盖范围」；**没问题就明确写「无问题」**，不许用「整体还不错」这类含糊话代替。

### 五、「验过了」的有效期

借原文「一个 PR 批准只对一个 commit 有效」：

- **我的验证结论只对当次改动有效。** 之后任何人再改一行，结论即失效，不能拿旧验证当新证据（这一条与 L2-5 同族，那里管「跑没跑」，这里管「跑的是不是当前这版」）。
- **我的自查通过 ≠ 可交付**（原文：机器人批准不能算人工批准）。我自查是必要条件，交付仍需 {owner} 看一眼，或留下可复核的实测证据。

## 🔧 第二层自动化：每轮注入（2026-08-14 下午）

**上午做的规则表和体检脚本都还不够**，因为想清楚了一件事：

> **记忆库里的东西是「数据」——要主动调用才生效，而调用这一步会漏。**
> **我的默认行为是「不用调用就自动发生」的。两者不在一个层面，所以数据永远打不过默认。**

这解释了 08-14 的四次同族错误（型号词 / 日期 / 交付说明 / 谎报「我加了」）：**每一次材料都在库里，每一次我在生产内容的那一刻没去调用它。**

### 🔴 对话层的自动注入**装不上**，四条路全部验证失败
